# FundFlow Backend

Kora-powered programmable fundraising platform backend built with FastAPI and SQLAlchemy.

## Overview

FundFlow provides the server-side infrastructure for a fundraising platform that enables:

- **Campaign Management**: Create and manage fundraising campaigns with defined financial structures
- **Kora Integration**: Virtual account creation, payment processing, and payout execution
- **Ledger System**: Immutable transaction tracking for complete financial transparency
- **Milestone Management**: Define and track fund release conditions
- **Beneficiary Verification**: Bank account resolution and verification
- **Webhook Processing**: Real-time transaction notifications from Kora

### Core Components

- **API Layer**: FastAPI routers for campaigns, contributions, milestones, payouts, beneficiaries, auth
- **Database Layer**: SQLAlchemy ORM with SQLite (dev) / PostgreSQL (prod) support
- **Kora Integration**: Virtual accounts, payments, payouts, webhook verification
- **Service Layer**: Business logic for campaign management, milestone processing, payout rules
- **Webhook Processor**: HMAC-verified webhook handling for real-time transaction updates

## Prerequisites

- Python 3.12+
- UV package manager (recommended) or pip
- Node.js (for frontend development)

## Clone & Setup

```bash
# Clone the repository
git clone <repository-url>
cd backend

# Create virtual environment and install dependencies
uv sync

# Or using pip:
pip install -r requirements.txt
```

## Configuration

Copy the example environment file and configure your settings:

```bash
cp .env.example .env
```

Edit `.env` with your configuration:

```env
# Application
APP_NAME=FundFlow
API_PREFIX=/api/v1
CORS_ORIGIN_LIST=http://localhost:3000,http://127.0.0.1:3000
DEBUG=true

# Database
DATABASE_URL=sqlite:///fundflow.db
# DATABASE_URL=postgresql://user:password@localhost/fundflow

# Kora Configuration
KORA_BASE_URL=https://api.getkora.com
KORA_API_KEY=your_kora_api_key
KORA_WEBHOOK_SECRET=your_webhook_secret
KORA_MOCK=false

# Security
JWT_SECRET=your_jwt_secret_key
JWT_ALGORITHM=HS256
JWT_EXPIRY_HOURS=24

# Development
AUTO_CREATE_TABLES=true
```

## Running the Server

### Development

```bash
# Start with auto-reload
uv run uvicorn app.main:app --reload

# Or specify host/port
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### Production

```bash
# Start without reload
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4
```

## Database Management

### Initialize Database

```bash
# Auto-create tables (dev only, enabled via AUTO_CREATE_TABLES=true)
uv run uvicorn app.main:app

# Or use Alembic for migrations
alembic upgrade head
```

### Alembic Migrations

```bash
# Create new migration
alembic revision --autogenerate -m "description"

# Apply migrations
alembic upgrade head

# Downgrade
alembic downgrade -1
```

## Security Considerations

The backend implements the following security measures:

- **JWT Authentication**: All protected endpoints require valid JWT tokens
- **Input Validation**: All inputs are validated using Pydantic models
- **HMAC Webhook Verification**: All Kora webhooks are verified using HMAC signatures
- **Rate Limiting**: Available on sensitive endpoints (configure as needed)
- **SQL Injection Protection**: All database queries use parameterized ORM queries
- **Financial Safety Rules**: 8 core rules for payment processing safety

### Financial Safety Rules (PRODUCT.md §52)

1. **Never trust a frontend payment-success response** - Always verify via Kora API
2. **Never trust an unsigned webhook** - All webhooks must have valid HMAC signatures
3. **Never process the same webhook twice** - Idempotency keys prevent duplicate processing
4. **Never treat a payout timeout as an automatic failure** - Manual review required
5. **Never execute a payout without sufficient campaign-attributable balance** - Balance checks before payout
6. **Never change an immutable financial transaction** - Ledger entries are append-only
7. **Never expose Kora secret credentials** - Secrets are environment variables only
8. **Never execute a payout to an unverified beneficiary** - Bank verification required first
